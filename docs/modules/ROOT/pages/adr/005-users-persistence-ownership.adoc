= ADR 005: Users persistence ownership
:status: accepted
:date: 2026-08-08

== Context

The `users` table is the first persisted domain model. Keeping its JPA mapping
and repository beside the user domain prevents the runnable application from
becoming the owner of domain persistence.

== Decision

Place the user persistence adapter in the `users` package under
`com.andrii.vaultnote.users.infrastructure.persistence`:

* `UserEntity` maps the `vaultnote.users` table;
* `UserJpaRepository` owns Spring Data access for `UserEntity`.

The application layer uses the users persistence package while the launcher
scans the shared `com.andrii.vaultnote` package tree. JPA entities remain
internal persistence models and are not REST response types.

Roles are not stored as a single field on `users`. A user can have multiple
roles through the `user_roles` table. The role is represented by the
`UserRole` enum and stored as a stable numeric `role_code`, rather than through
a separate `roles` table. The current codes are `1` for `USER` and `2` for
`ADMIN`.

== Consequences

* User persistence changes remain localized to the `users` package.
* Future application services can depend on a users-owned persistence boundary.
* The application package contains wiring rather than user-specific persistence
  behavior.
* Role assignments remain normalized and can represent multiple roles per user.
* Adding a role requires a new enum code and a corresponding database
  constraint migration.
* DTOs and API contracts must be introduced before exposing user data over REST.

== Status

Accepted.
