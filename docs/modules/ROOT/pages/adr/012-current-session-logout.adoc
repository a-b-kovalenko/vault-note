= ADR 012: Current-session logout
:status: accepted
:date: 2026-08-11

== Context

VaultNote keeps the access JWT stateless and stores the refresh session in the
database. Logout must prevent the client from obtaining another access token,
remove the browser cookie, and behave safely when the client has already lost
or invalidated its cookie.

== Decision

Implement `POST /api/v1/auth/logout` as an idempotent refresh-session operation:

* accept the refresh token from the `HttpOnly` cookie when it is present;
* hash it and revoke only the matching active refresh-token record;
* ignore missing, unknown, or already revoked tokens; an expired token is
  harmless and may be marked revoked as part of the same operation;
* always return `204 No Content` and a replacement cookie with an empty value
  and `Max-Age=0`;
* allow the endpoint through the HTTP security filter because its credential is
  the refresh cookie, not a Bearer access token.

Logout does not revoke an already issued access JWT. The token remains valid
until its expiry, while the revoked refresh session prevents further token
rotation.

== Consequences

* Repeating logout is safe and does not reveal whether a token existed.
* The current refresh session cannot be used to obtain a new access token.
* Other login sessions and token families remain active.
* Immediate access-token revocation would require a separate stateful denylist
  or token-version mechanism.
* Logout must include the CSRF token header when called by the browser client;
  the shared policy is defined by ADR 013.

== Status

Accepted and implemented by `AuthController`, `RefreshTokenServiceImpl`,
`RefreshTokenCookieFactory`, and `RefreshTokenIntegrationTest`.
