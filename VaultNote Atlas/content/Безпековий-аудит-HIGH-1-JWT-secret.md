## 📝 TL;DR

**Статус:** `RESOLVED`  
**Рівень:** `HIGH`

Застосунок мав відомий запасний JWT secret. Якщо backend запускався без
`VAULTNOTE_JWT_SECRET`, будь-хто міг створити власний JWT і видати себе за
будь-якого користувача або адміністратора. Проблему виправлено: secret тепер
обов'язковий, а відомі та слабкі значення відхиляються під час запуску.

## У чому була проблема

JWT підписується секретним ключем. Backend довіряє claims токена лише після
перевірки цього підпису.

У конфігурації був fallback на значення:

```text
local-development-only-secret-change-me-please
```

Це значення було відоме з коду. Атакувальнику не потрібен був акаунт: він міг
підписати HS256 JWT із довільним `sub` і роллю `ADMIN`.

## Що міг зробити атакувальник

Після запуску backend без справжнього secret атакувальник міг:

1. створити валідний на вигляд JWT;
2. вказати в ньому ID іншого користувача;
3. додати роль `ADMIN`;
4. читати список користувачів і чужі нотатки;
5. виконувати дії від імені іншої людини.

Перевірки issuer, expiry, алгоритму та ролей не допомагали, бо сам ключ
підпису був відомий.

## Як проблему вирішено

- Прибрано default secret з основного `application.yaml`.
- `VAULTNOTE_JWT_SECRET` тепер обов'язковий.
- Backend завершує startup, якщо secret відсутній, порожній, коротший за
  мінімальну довжину або дорівнює відомому development placeholder.
- Для локального запуску secret зберігається в ignored
  `application-local-secrets.yaml`.
- Integration tests отримують окремий явний test secret.
- Якщо старий fallback уже використовувався у доступному середовищі, ключ
  потрібно ротувати.

## Як перевірено

Unit-тести перевіряють відсутній, порожній, короткий і відомий placeholder
secret. Integration suite запускається з явним test secret. Запуск без
`VAULTNOTE_JWT_SECRET` має завершуватися помилкою конфігурації.

## Головний висновок

Секрети не можна зашивати у fallback, навіть якщо він названий
development-only. Для локальної зручності краще мати ignored файл із випадковим
значенням, а не спільний ключ у репозиторії.
